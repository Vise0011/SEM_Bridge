# 시스템 카드

## 목적과 사용 환경

기업마당 금융 공고의 근거를 찾아 합성 기업 프로필의 명시적 조건을 확인하는 로컬 프로토타입입니다.
2026-10-07 개발 세션에서 공식 인증키로 공고 30건과 PDF 16건을 수집했습니다.
PDF가 아닌 첨부 14건은 지원하지 않아 건너뛰었습니다. 이 숫자는 수집 확인이며 성능 평가가 아닙니다.

현재 개발 PC에서 PostgreSQL 연결과 Docker 실행 파일을 찾지 못해 라이브 저장 검증은 SQLite에서 수행합니다.
PostgreSQL·Neo4j 경로는 GitHub Actions의 임시 서비스 통합 테스트로 검증하도록 구성했습니다.
실제로 실행되지 않은 CI 검증을 성공으로 간주하지 않습니다.

## 결정과 한계

- 최종 자격 심사·신용평가·자동 신청을 수행하지 않습니다.
- 외부 LLM을 호출하지 않습니다. 수동으로 검토한 구조화 조건을 Python 규칙으로 비교합니다.
- 미승인 공고, 미지원 조건, 부분 검토, 정보 누락, 근거 불일치는 확인 필요입니다.
- 공식 승인은 정확한 저장 페이지와 최신 메타데이터 및 PDF 해시에 묶입니다.
- 공고·PDF 변경 시 이전 승인은 최신 진단에 사용하지 않으며 과거 결과는 그대로 보존합니다.
- 부분문자열 검색을 사용하고 의미 기반·벡터 검색은 없습니다.
- OCR 필요 여부는 텍스트 길이 휴리스틱입니다. OCR 자체나 표 구조 복원은 지원하지 않습니다.
- 의심 문구 표시도 휴리스틱이므로 완전한 악성 문구 탐지로 해석할 수 없습니다.
- 합성 데모에는 2026년 신청기간을 사용합니다. 기준일에 따라 만료 결과가 나옵니다.
- 인증·권한 관리가 없는 로컬 개발 API입니다. 공개 서버 배포에는 인증·접근 통제·TLS 설계가 필요합니다.
- 실제 기업 개인정보를 처리하도록 설계·평가하지 않았습니다.

## 검증 범위

자동 테스트는 규칙 경계, API 계약, 다운로드 제한, 의심 문구, 인용 일치,
현재 버전 승인, PDF 교체, 저장 후 재조회, 동시 재시도와 입력 충돌을 다룹니다.
공인 정답 데이터셋, 정확도/F1, 추출 성능, 대규모 부하, LLM 평가 수치는 없습니다.
